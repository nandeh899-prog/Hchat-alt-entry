# 主题模块「已修好」冻结清单（REGRESSION FREEZE）

> 起因：用户 2026-11-26 明确要求——**修复过的东西，后面版本不要再去改它**。
> 主题这条线已经反复出现「修好 A → B 回归 → 再修 B → A 回归」的死循环，
> 根因不是能力问题，而是每次为了修新问题都去动已经验证通过的代码路径。
>
> 本文件是这个问题的硬性约束。规则只有三条。

## 规则

1. **只允许补强，不允许改判定**
   已冻结的路径（判据、作用对象、执行时机）一律不改。若新问题确实需要在这条路径上做事，
   只能「新增一个独立分支 + 独立日志标签 + 独立状态位」，且默认行为与冻结前完全一致。

2. **回退优先于叠加**
   一旦真机验证发现某个版本让已冻结行为回归，处理方式是 `git revert` 掉引入回归的那个提交，
   回到上一个验证通过的版本，**不允许在回归版本上继续打补丁**。

3. **未经真机验证不算修好**
   只有用户肉眼确认 + 日志无异常 + 重启后仍成立的，才允许写进本文件的「已冻结」列表。
   每个提交仍按 AGENTS.md 要求写「未经真机验证」。

```bash

# ② 整条线回到基线（远端 alt-entry 也回退；force-with-lease 有保护，别人推过会失败）

git revert <出错的提交 sha>
```
